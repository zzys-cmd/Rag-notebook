# 名词表

> 只收这套代码里真出现过的词。每个词一行，不展开。
> 看不懂哪个就翻这里，不要背。

## 并发（第 3、4 节）

| 词 | 意思 |
|---|---|
| 协程 | `async def` 定义的函数。调用它不会执行函数体，只返回一个协程对象 |
| 事件循环 | asyncio 里唯一在跑的调度器，轮流推进能往下走的协程 |
| `await` | 在协程里暂停自己，把控制权还给事件循环；等的东西完成后从原处继续 |
| 阻塞 | 一个调用在返回前占着线程不放，期间这个线程什么也干不了 |
| `asyncio.to_thread` | 把同步函数丢到线程池执行，返回一个可以 `await` 的对象 |
| 线程池 | `ThreadPoolExecutor`，预先开一组线程，提交的任务排队执行 |
| 队列 | `queue.Queue`，线程之间传数据的容器；`maxsize` 满了 `put` 会卡住。本项目两处都叫"队列"但实现不同，见下两行 |
| 入队（Day2） | `TaskQueue.put(...)`，进内存队列（`rag/task_queue.py`，`knowledge_service.py:287` 建 `maxsize=10`）。进程死了里面就没东西了 |
| 入队（Day3） | 往 MySQL 的 `graph_build_tasks` 插一行 `status='pending'`。**不是内存队列**，进程死了行还在，worker 每 2 秒 `SELECT` 一条。行业里叫持久化任务队列（Celery / RQ 也是这一类，本项目没用它们） |
| 背压 | 下游慢时逼上游停下来等，防止数据在内存里堆积 |
| SSE | 服务器保持连接、一条条往回推消息的 HTTP 方式，`media_type="text/event-stream"` |
| 流式 | 不攒到最后一次性返回，做一点发一点 |
| worker | 行业通用词，指常驻后台、循环取任务干的执行体。本项目里具体就是 `graph_worker.py` 的 `run_worker_loop`，没有 Worker 基类、没有 Celery，`core/background_init.py:142` 一个 `asyncio.create_task` 起的就是它。**它不是事件循环**，它是被事件循环调度的一个协程 |

## 检索（第 5～8 节）

| 词 | 意思 |
|---|---|
| `RetrievalPlan` | 检索计划。字段：`need_retrieval` / `steps` / `allow_web_fallback` |
| `RetrievalStep` | 一条检索指令。字段：`tool` / `query` / `top_k` |
| tool | 工具名，枚举，五个：`search_notes` / `search_knowledge_base` / `search_graph` / `hybrid_search` / `web_search` |
| `top_k` | 这一条要取回几条结果，代码里被限在 1..5 |
| embedding | 把一段文字变成一串数字（向量），语义相近的文字，数字也相近 |
| 向量索引 | Neo4j 里按向量距离查节点的索引，`chunk_embedding_index` |
| 全文索引 | 按关键词查节点的索引，`chunk_text_index`，打分类似 TF-IDF/BM25 |
| 余弦相似度 | 两个向量的夹角余弦，范围 0~1，越大越像 |
| RRF | 按名次融合多路结果：每路第 `rank` 名贡献 `1/(60+rank)`，两路都出现的相加 |
| `Chunk` | 一个块，切片的产物，带 `user_id` / `original_filename` / `md5` |
| `ChunkHit` | 从库里查出来的一条块，还没转成 `Evidence` |
| `Evidence` | 给模型看的证据。字段：`source` / `title` / `content` / `score` |
| 可答性 | 现有证据够不够回答问题，不够就走联网 |

## 数据与框架

| 词 | 意思 |
|---|---|
| Neo4j | 图数据库。这个项目的块和实体都存在这里 |
| MySQL | 关系型数据库。这个项目用它存记录和状态：`graph_docs`（传过哪些文件）/ `graph_build_tasks`（还有什么没抽）/ `graph_extract_logs`（抽成没成）。**不存内容**，内容在 Neo4j |
| Cypher | Neo4j 的查询语言，相当于 SQL |
| `MERGE` | Cypher 的"匹配到了就复用，匹配不到就新建"。等价于 SQL 的 `INSERT ... ON DUPLICATE KEY UPDATE`。写法是 `MERGE` 里只放身份字段（如 `id` / `user_id`），内容字段用后面的 `SET` 覆盖——内容字段放进 `MERGE` 会导致内容一变就匹配不上、又建一个新节点 |
| `UNWIND` | 把列表摊开逐行执行，相当于"对数组里每个元素跑一遍" |
| `MATCH` | 只查，不建。查不到就返回空，什么都不发生 |
| 节点 / 边 | Neo4j 里的点（`(:Chunk)`、`(:Entity)`）和关系（`-[:MENTIONS]->`） |
| pydantic | Python 的数据校验库。用 `BaseModel` 声明字段和类型，不合规直接报错 |
| 降级 | 主路径失败时退到更简单的做法，保证流程还能走完 |
| md5 | 文件内容的指纹。同一份文件算出来一样，用来查重 |
| `json.dumps` | Python 对象 → JSON 字符串。`graph_service.py:269` 用它把 `payload` 塞进 MySQL 的 `Text` 列 |
| `json.loads` | JSON 字符串 → Python 对象。`graph_service.py:391` 用它把 `payload` 还原成 dict，之后才能 `.get("chunks")` |
| `ensure_ascii=False` | `json.dumps` 的参数，让中文原样存，不转成 `\u4e2d\u6587` |
